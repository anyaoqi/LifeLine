# Life-Point 产品需求规格

> 本文是产品的「唯一真相源」：先看这里理解要做什么，再看 [开发规划](./开发规划.md) 看怎么做、做到哪了，看 [设计理念与UI指南](./设计理念与UI指南.md) 看长什么样。
> 最近更新：2026-07-26

---

## 1. 一句话定义

**Life-Point 是一个人生事件档案库：把一个人从出生到现在发生过的所有事情，按时间轴完整、清晰地记录下来，随时能丝滑地回看。**

不是日记（不追求每天写），不是待办（不面向未来计划），而是**回顾型的人生索引**。

## 2. 用户到底要记什么

真实使用中，事件天然分成两种量级，二者必须共存且能分开看：

| 量级 | 说明 | 典型例子 | 特征 |
|------|------|----------|------|
| **人生大事**（里程碑） | 改变人生阶段或不可重复的关键节点 | 上幼儿园、上小学、上初中、上高中、上大学、参加工作、结婚、生孩子、奶奶去世、买房、搬到新城市 | 数量少（几十条）、必须一眼看到、常常是**时间区间**（如小学 2010–2016） |
| **人生小事**（日常闪光点） | 值得记住但不改变人生走向的经历 | 过生日、去新疆旅游、第一次出国、第一次坐飞机、考到驾照、养了只猫、看了某场演唱会 | 数量多（几百条）、按需展开、多为**时间点** |

**由此产生的第一条硬需求：事件必须有「重要程度」维度**，时间轴默认可以「只看大事」，展开后才看到小事。否则记满 300 条小事之后，人生主干会被淹没 —— 这是这类应用最容易死掉的地方。

## 3. 核心需求（P0，缺一不可）

### 3.1 清晰的时间记录 —— 允许"记不清"

回忆往事时，日期精度天然是不一致的：结婚记得到天，上幼儿园可能只记得年份，奶奶去世可能只记得"2015 年冬天"。强制填完整日期会让用户直接放弃录入。

- 必须支持三档**日期精度**：`year`（2003 年）/ `month`（2003 年 9 月）/ `day`（2003 年 9 月 1 日）
- 精度要**如实展示**，不能把"2003 年"显示成"2003年1月1日"，那是伪造记忆
- 排序时按可比较的起始时间戳，同一时间粒度内保持稳定顺序
- 每个事件都要能显示**当时的年龄**（如「6 岁 3 个月」）和**距今多久**，这是人生时间轴独有的价值
- 时间区间事件要显示**持续时长**（如「6 年」）

### 3.2 时间点 vs 时间区间 —— 两类事件必须泾渭分明

这是与「日期精度」同等重要的第二个时间维度。人生事件天然有两种时间形态：

| 形态 | 定义 | 例子 | 跨度 |
|------|------|------|------|
| **时间点** `point` | 发生在某一天/某月/某年的单次事件 | 结婚、孩子出生、奶奶去世、拿到驾照、第一次出国 | 无跨度 |
| **时间区间** `period` | 有起点和终点的一段经历 | 上高中（3 年）、上小学（6 年）、在某公司工作（4 年）、去新疆旅游（8 天）、住在广州（5 年） | 几天 / 几个月 / 几年，都要支持 |

**硬需求：**

1. **录入时明确二选一**：表单顶部第一个决策就是「时间点 / 时间区间」分段切换器，切换后日期区域即时变形（单个日期 ↔ 起止双日期），不允许用户填到一半才发现选错。
2. **区间跨度自适应**：几天、几个月、几年都是合法区间，UI 与文案不得假设区间一定是"多年"。持续时长按跨度自动选择单位（`8 天` / `3 个月` / `3 年` / `4 年 2 个月`）。
3. **区间可以未结束**：`isOngoing=true` 表示「至今」（当前的工作、现在住的城市），此时不填结束日期。
4. **起止各自独立的日期精度**：允许「2010年9月1日 – 2016年」这种一头清楚一头模糊的真实情况。
5. **校验**：结束日期不得早于起始日期；`isOngoing` 与 `endDate` 互斥。
6. **查看时一眼可辨**：时间轴、卡片、列表、搜索结果四处都必须能不假思索地区分两类事件 —— 点事件是轴上的一个**节点**，区间事件是轴上的一段**色带**（视觉规范见设计指南）。
7. **跨年区间不被年份分组切碎**：上高中 2016–2019 只是一个事件，不能在 2016/2017/2018/2019 各出现一次；它应作为连续色带贯穿这几年，仅在起始年份挂卡片。
8. **筛选可按形态**：支持「只看阶段（区间）」查看人生骨架，或「只看节点」查看具体时刻。

### 3.3 人生阶段（区间事件）要成为时间轴的骨架

上幼儿园 → 小学 → 初中 → 高中 → 大学 → 工作，本质是一串首尾相接的**阶段**，不是六个孤立的点。

- 区间事件在时间轴上渲染为**贯穿的竖向色带 / 泳道**，而不是一张普通卡片
- 点事件叠加在阶段带之上，用户能立刻看出「第一次出国」发生在「大学」期间
- 阶段允许重叠（在读书期间兼职工作）

### 3.4 增删改查必须便捷

- **增**：浮动 + 按钮，从任何页面一键新增；表单字段自上而下为 标题 → 日期（含精度切换）→ 重要程度 → 分类 → 描述；支持连续添加（保存后不关闭表单）
- **人生模板一键铺底**：填了出生日期后，可按学制自动生成幼儿园/小学/初中/高中/大学等阶段事件草稿，用户微调即可 —— 解决「冷启动要手打 20 条」的最大阻力
- **改**：卡片上直接进入编辑，数据预填；时间轴外另提供**列表/表格视图**，用于快速连续修改多条（时间轴适合看，列表适合改）
- **删**：二次确认 + **30 秒内可撤销**（软删除后清理），避免误删不可恢复的记忆
- **查**：关键词搜索（标题+描述）、分类多选、重要程度筛选、年份区间筛选，条件可叠加并显示命中数量

### 3.5 丝滑的浏览体验

时间轴是主视角，浏览手感是产品的核心竞争力：

- **年份导航尺**：侧边常驻年份/年龄标尺，点击直达，滚动时高亮当前年份
- **吸顶年份标签**：滚动过程中当前年份始终可见，不会「迷失在时间里」
- **缩放粒度**：可在「按年 / 按月 / 全部」之间切换密度，人生 30 年一屏概览也能看
- **性能底线**：500+ 事件时滚动不掉帧（必要时虚拟滚动 + 动画降级）
- **键盘导航**：↑↓ 在事件间移动，Enter 展开，Esc 收起，`/` 聚焦搜索
- **尊重系统偏好**：`prefers-reduced-motion` 时关闭动画

### 3.6 数据安全与隐私

- 纯本地存储（IndexedDB），不上传
- 一键导出 JSON（可备份/迁移）+ 导入恢复
- 清除数据需明确二次确认

## 4. 次要需求（P1，让人愿意长期用）

- 事件配图（1 张封面图，存 IndexedDB Blob）
- 地点、参与人、心情标签
- 统计面板（年度事件数、分类分布、活跃月份）
- 导出时间线为图片 / PDF
- 主题与时间轴风格定制

## 5. 明确不做（当前范围外）

- 未来计划 / 待办 / 提醒（这是别的产品）
- 社交流、点赞、评论
- 每日打卡式日记
- 多人协作编辑同一条时间线

## 6. 数据模型（目标态）

```typescript
type EventType = 'point' | 'period';
type DatePrecision = 'year' | 'month' | 'day';
/** 1=日常小事 2=值得记 3=重要 4=大事 5=人生里程碑 */
type Importance = 1 | 2 | 3 | 4 | 5;

interface LifeEvent {
  id: string;
  userId: string;
  title: string;
  type: EventType;
  date: string;                 // 起始日期 ISO（按精度补全，展示时按精度裁剪）
  datePrecision: DatePrecision; // 新增：如实反映"记不清到哪一天"
  endDate?: string;             // type='period'
  endDatePrecision?: DatePrecision;
  isOngoing?: boolean;          // 区间尚未结束（如「现在的工作」）
  importance: Importance;       // 新增：大事/小事分层的依据
  category: EventCategory;      // 8 类
  description?: string;
  location?: string;            // P1
  participants?: string[];      // P1
  coverImage?: string;          // P1
  mood?: string;                // P1
  createdAt: string;
  updatedAt: string;
  deletedAt?: string;           // 软删除，支撑撤销
}
```

**与现状的差距**（见开发规划中的迁移计划）：`datePrecision`、`importance`、`isOngoing`、`deletedAt` 均为新增字段，需要 Dexie schema 升级并对旧数据填默认值（`datePrecision='day'`、`importance=3`）。

## 7. 验收场景

用这几个场景验收，而不是逐条对功能清单打勾：

1. **冷启动 10 分钟**：新用户填完出生日期，用模板铺出 5 个学习阶段，再补 10 条大事，全程不被强制填写记不清的日期。
2. **两种时间形态录入**：录「2019年6月8日 高考」为时间点，录「2016年9月–2019年6月 上高中」为时间区间，再录「2023年8月10日–8月18日 去新疆旅游」这种 8 天的短区间；三者在时间轴上形态一眼可辨，短区间不会被渲染成一根看不见的线。
3. **只看主干**：切到「只看大事」，屏幕上从出生到现在的人生主线一屏可览，阶段带连续无断点。
4. **找回一件小事**：想起「那次去新疆是哪年」，搜「新疆」→ 命中 → 点击 → 时间轴定位并高亮，显示当时年龄。
5. **批量整理**：在列表视图连续修正 10 条事件的日期和分类，不需要来回开关模态框。
6. **误删可救**：删掉一条重要事件后 30 秒内点撤销，数据完整恢复。
7. **压力测试**：导入 500 条事件，滚动整条时间线全程流畅，年份导航跳转即时响应。
