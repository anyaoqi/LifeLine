## 1. 项目概述与目标

**项目名称**: Life-Point  
**项目描述**: 一个记录个人从出生到现在全部人生事件的档案库 —— 既记上幼儿园/上大学/参加工作/结婚/生孩子/亲人离世这类**大事**，也记过生日/去新疆旅游/第一次出国这类**小事**，通过时间轴完整、清晰地回看自己的人生轨迹。
**目标用户**: 希望记录和反思人生重要时刻的个人用户  
**核心价值**: 用一条时间轴承载一个人的全部历史 —— 时间记录清晰、增删改查便捷、浏览体验丝滑。

**四条不可妥协的产品红线**（任何迭代都不能破坏）：
1. **时间必须清晰且如实** —— 支持年/月/日三档精度，记不清就不逼用户编造
2. **时间点与时间区间必须泾渭分明** —— 录入时二选一，时间轴上点是节点、区间是贯穿色带，跨度从几天到几年都要成立
3. **大事不能被小事淹没** —— 重要程度分层 + 默认只看主干
4. **浏览必须丝滑** —— 500 条事件下滚动不卡、年份跳转即时

## 3. 技术栈推荐与理由

### **前端框架: Vue 3 + TypeScript**
- ✅ 学习曲线平缓，易于吸引开源贡献者
- ✅ 官方生态完善（Router、Pinia、VueUse等）
- ✅ TypeScript支持优秀，开发体验好
- ✅ 相比React更轻量级，适合个人项目

### **状态管理: Pinia**
- ✅ Vue官方推荐，是Vuex的现代化替代
- ✅ API简洁直观，易于学习和维护
- ✅ 完美的TypeScript支持
- ✅ 包体积小（~2.5KB）

### **数据存储方案**

**MVP+Phase 2 阶段**:
- **IndexedDB** (dexie.js): 存储事件数据（支持大容量、复杂查询）
- **localStorage**: 存储用户设置、主题、缓存
- **特点**: 完全本地化，无后端依赖，支持离线使用

**Phase 3+ 阶段**:
- **后端API**: 用户认证和数据同步
- **PostgreSQL**: 关系型数据库，支持事务和复杂查询
- **Redis**: 缓存和会话管理（可选）

### **UI框架: Tailwind CSS**
- ✅ 原子化CSS，高度定制化，学习成本低
- ✅ 支持暗黑模式开箱即用（`darkMode: 'class'`）
- ✅ 生产环境CSS体积小（tree-shaking）
- ⚠️ 实际采用 **Tailwind v3.4**（原模板曾误配 v4，已降级以匹配现有配置写法）
- 📝 MVP 未引入 Headless UI —— 模态框、按钮等组件均自行用 Tailwind 实现

### **可视化方案**
- **MVP**: ❌ 未使用任何图表库 —— 时间线采用**纯 CSS 自定义实现**（中心竖线 + 节点 + 卡片），更贴合设计文档的温馨简约美学
- **Phase 3+ 统计面板**: 届时再评估引入 Chart.js（轻量）或 D3.js（灵活自定义）

### **其他核心工具**

| 工具 | 选择 | 状态 | 理由 |

| 测试框架 | Vitest + Vue Test Utils | ⏳ Phase 3 | 轻量级，与Vite无缝集成 |
| 代码规范 | ESLint + Prettier | ⏳ Phase 3 | 业界标准 |

```typescript
type EventType = 'point' | 'period';
type DatePrecision = 'year' | 'month' | 'day';
type Importance = 1 | 2 | 3 | 4 | 5;
type EventCategory =
  | 'education' | 'work' | 'life' | 'travel'
  | 'love' | 'health' | 'achievement' | 'other';

interface LifeEvent {
  id: string;
  userId: string;
  title: string;
  type: EventType;                 // 时间点 / 时间区间
  date: string;                    // 起始日期 ISO（用精度对应的首日作排序锚点）
  datePrecision: DatePrecision;    // 年 / 月 / 日，如实展示
  endDate?: string;                // 区间结束日期
  endDatePrecision?: DatePrecision;// 起止精度可不同
  isOngoing?: boolean;             // 区间延续至今，与 endDate 互斥
  importance: Importance;          // 1=小事，5=人生里程碑
  description?: string;
  category: EventCategory;
  createdAt: string;
  updatedAt: string;
  deletedAt?: string;              // 为后续 30 秒撤销预留
}
```

**Dexie v2 → v3 迁移规则**（已实现于 `storageService.ts` 的 `upgrade` 钩子 + `normalizeEvent` 兜底）：
- `datePrecision` 缺失 → `'day'`（旧数据都是完整日期）
- `importance` 缺失 → `3`（普通），避免旧数据在「只看大事」下全部消失
- `endDatePrecision` 缺失且有 `endDate` → 跟随 `datePrecision`
- 新增索引：`importance`、`deletedAt`（列表与筛选查询用）
- 常规读取默认排除 `deletedAt` 已设置的软删除事件
- 导出格式 `version` 升到 `'2.0'`；导入 `'1.0'` 数据时套用同一套默认值

## 8. 关键技术决策说明

### **为什么选择Vue 3而不是React?**
- Vue学习曲线更平缓，对新手更友好
- 官方生态完善一致，不存在选择困难
- 本项目规模适中，不需要React的灵活性
- 有利于吸引更多开源贡献者

### **为什么使用IndexedDB而不是localStorage?**
- localStorage限制~5-10MB，IndexedDB支持更大容量
- 支持复杂数据结构、索引和事务
- dexie.js提供简洁易用的API
- 性能更优，适合数据查询和更新

### **为什么选Tailwind而不是其他CSS框架?**
- 原子化设计，高度定制化
- 生产CSS体积小（通过tree-shaking）
- 学习成本低，易于上手
- 完美支持暗黑模式

### **为什么暂不使用后端?**
- MVP阶段快速验证核心价值
- 降低项目复杂度和维护成本
- 用户数据完全本地化，隐私更好
- 后期按需添加后端功能

**Q: 如何吸引贡献者?**
