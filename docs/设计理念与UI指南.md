# Life-Point 设计理念与UI指南

## 🎨 核心设计理念

### **应用目的**
帮助用户清晰、完整地看到自己从出生到现在的所有人生事件记录，让每个人生节点都清晰可见，支持回顾、反思和记录自己的人生轨迹。

### **设计三大支柱**
1. **清晰的时间线** - 时间轴是主视角，一眼看透人生全景
2. **丝滑的交互体验** - 流畅的动画、快速的响应、舒适的交互
3. **温馨简约的美学** - 页面简洁，UI元素舒适温暖，有人味

## ✨ 核心交互体验

### **时间线交互**（最核心）

#### **纵向时间线（MVP）**
- 📌 出生日期作为起点（时间轴底部）
- 📍 事件按时间顺序从下至上排列
- 🎯 事件卡片横向分布在时间轴两侧，形成"之字形"排列
- 💫 悬停事件卡片时，卡片轻微放大和阴影增强，时间轴节点高亮
- ⚡ 点击卡片展开详情，有平滑的高度动画
- 🔄 滚动时间线时，过去的事件逐渐变灰（表示已过去），当前和未来保持明亮

#### **关键动画**
```
卡片进入: 淡入 + 轻微向上滑动 (300ms, ease-out)
悬停: 缩放 1.02 + 阴影增强 (200ms, ease-out)
展开详情: 高度平滑展开 (400ms, ease-out)
滚动时间线: 平滑滚动 (无生硬跳跃)
页面切换: 淡入淡出过渡 (200ms)
```

### **事件管理交互**

#### **添加事件**
- 🔘 浮动按钮（右下角），用"+号"图标
- 📝 点击打开模态框，表单默认聚焦在事件标题输入框
- 💾 保存时有微妙的"保存成功"反馈（短暂的绿色勾选动画）
- ✍️ 表单字段从上到下：标题 → 日期 → 分类 → 描述

#### **编辑事件**
- ✏️ 事件卡片上点击"编辑"图标进入编辑模式
- 🔄 数据预填充，用户可修改任何字段
- 🗑️ 底部有"删除"按钮，点击时需确认

#### **删除事件**
- ⚠️ 删除前显示确认对话框："确定要删除这个事件吗？此操作无法撤销。"
- 🔙 提供"撤销"功能，在30秒内可恢复

### **搜索与筛选**（Phase 2+）
- 🔍 搜索框位于页面顶部，支持实时搜索
- 🏷️ 分类筛选：以小芯片形式展示，可多选
- ⏰ 年份快速跳转：侧边栏显示年份列表，点击跳转到该年

## 🎭 页面设计规范

### **整体布局**

#### **标准页面结构**
```
┌─────────────────────────────────────┐
│ Header (固定)                        │
│ Logo | 标题 | 用户菜单 | 主题切换   │
├─────────────────────────────────────┤
│                                     │
│  Sidebar (可选)   │  Main Content   │
│  导航/分类菜单    │  时间线或内容   │
│  用户信息         │                 │
│                  │                 │
│                  │  [+ 按钮]       │
└─────────────────────────────────────┘
```

### **Header 设计**
- 高度: 64px（包含内边距）
- 背景: 纯白或浅暖色 (#F8F7F5)
- 分隔线: 1px 浅灰 (#E5E5E5)
- 左侧: Life-Point Logo + 项目名称
- 中央: （保留给未来功能）
- 右侧: 搜索（可选）| 主题切换 | 用户菜单（档案/设置/关于）

### **时间线页面**
- 中心对齐，时间轴为竖直线
- 时间轴线宽: 2px，颜色: #D4A574
- 节点圆圈: 12px 直径，填充: #D4A574，悬停时放大到 16px
- 事件卡片: 最大宽度 400px（确保清晰阅读）
- 左右对称或交替排列，取决于屏幕宽度
- 移动设备: 所有卡片排在时间轴一侧，防止左右切换

### **事件卡片设计**
```
┌─────────────────────┐
│ [分类色块] 事件标题  │ ← 卡片标题区
├─────────────────────┤
│ 2024年6月15日        │ ← 时间显示
│ 分类: 学业           │ ← 分类标签
├─────────────────────┤
│ 这是事件的描述内容   │ ← 描述区（省略号截断）
│ 支持多行显示...     │
├─────────────────────┤
│ [编辑] [删除] [展开] │ ← 操作按钮
└─────────────────────┘

悬停时:
- 卡片阴影增强
- 背景轻微变浅
- 操作按钮更明显
```

### **个人档案页面**
- 简洁布局，突出用户信息
- 头像（圆形，120px）+ 用户名 + 出生日期（计算年龄）
- 简介区域（可编辑）
- 统计卡片（Phase 2+）：总事件数、最早事件、最新事件等
- 快速操作按钮：编辑档案、导出数据、设置

### **底部（Footer）**
- 简约设计，仅包含必要信息
- 版本号、开源链接、反馈链接
- 可选: 一句鼓励的文案，如"记录生活，反思人生 ✨"

## 🎬 动画与过渡

### **动画时长指南**
- 快速反馈: 200ms (按钮悬停、输入框焦点)
- 标准动画: 300ms (卡片进入、淡入淡出)
- 较长动画: 400-500ms (模态框进入、复杂展开)
- 过度动画: > 600ms (避免，容易显得卡顿)

### **关键动画清单**
| 操作 | 动画类型 | 时长 | 缓动函数 |
|------|--------|------|--------|
| 页面加载 | 淡入 | 300ms | ease-out |
| 卡片进入 | 淡入 + 上滑 | 300ms | ease-out |
| 卡片悬停 | 缩放 + 阴影 | 200ms | ease-out |
| 打开模态框 | 淡入 + 向下滑入 | 300ms | ease-out |
| 关闭模态框 | 淡出 + 向下滑出 | 200ms | ease-in |
| 保存成功 | 勾选动画 | 600ms | ease-out |
| 滚动到事件 | 平滑滚动 | 500ms | ease-in-out |
| 分类切换 | 内容淡入淡出 | 200ms | ease-in-out |

## 📱 响应式设计

### **断点设置**
```
Mobile:     < 640px   (竖屏手机)
Tablet:     640-1024px (平板)
Desktop:    > 1024px   (桌面)
```

### **各设备的时间线展示**
| 设备 | 时间线宽度 | 卡片排列 | 字体大小 |
|------|----------|--------|--------|
| Mobile | 100% | 单侧排列（左或右） | 14-16px |
| Tablet | 80% | 两侧交替 | 15-17px |
| Desktop | 70% 居中 | 左右对称 | 16-18px |

### **移动端优化**
- 浮动 + 按钮放在易触及位置（下方）
- 事件卡片宽度自适应，最小 280px
- 模态框全屏或大部分屏幕宽度
- 字体大小不小于 16px（避免自动缩放）

## ♿ 可访问性规范

### **键盘导航**
- Tab 键可聚焦所有交互元素
- Enter 键激活按钮/链接
- Escape 键关闭模态框/菜单
- 上下箭头在时间线中导航事件
- Ctrl/Cmd + F 打开搜索

### **屏幕阅读器**
- 所有图标都有 aria-label
- 表单字段有关联的 label
- 重要信息有语义化标记
- 时间轴用 <ol> 标签表示有序列表

### **色彩对比度**
- 所有文字与背景对比度 ≥ 4.5:1
- 交互元素对比度 ≥ 3:1
- 避免只用颜色传达信息（配合文字或图标）

## 🎯 用户体验检查清单

### **加载体验**
- [ ] 页面首屏加载时间 < 2秒
- [ ] 事件列表渲染流畅（虚拟列表，支持 100+ 事件）
- [ ] 加载过程有进度反馈

### **输入体验**
- [ ] 表单字段有清晰的焦点样式
- [ ] 输入错误有即时反馈（不是提交时才提示）
- [ ] 成功保存有视觉反馈（不仅仅是消息提示）
- [ ] 支持回车键快速保存

### **导航体验**
- [ ] 当前位置清晰（面包屑或高亮导航）
- [ ] 返回上级操作便利（浏览器返回键 + UI 返回按钮）
- [ ] 页面切换过渡平滑，不出现闪烁

### **移动端体验**
- [ ] 所有按钮大小 ≥ 48×48px（易点击）
- [ ] 模态框宽度适配，不全屏占用（留出边距）
- [ ] 虚拟键盘出现时表单不被遮挡

### **深色模式体验**
- [ ] 所有元素在深色模式下都清晰可见
- [ ] 图片/头像在深色模式下不过曝
- [ ] 不强制使用深色模式，尊重用户选择

## 💡 设计灵感参考

虽然 Life-Point 有自己独特的风格，但以下产品的设计思想可以参考：

- **Apple Reminders**: 简洁、清晰的 UI，流畅的交互
- **Day One**: 温暖的配色，个人日记的整体感觉
- **Timeline.app**: 可视化时间线的呈现方式
- **Motion**: 优秀的动画细节和过渡
- **Notion**: 模块化的灵活布局

**关键学习点**:
- 少即是多：删除所有非必要 UI 元素
- 微交互：细微的动画让操作感觉更贴心
- 信息层级：重要信息优先展示，次要信息隐藏在折叠下
- 一致性：确保所有页面的交互方式统一

## 🎨 设计工作流（开发时参考）

### **前期设计产出物**（可选，非必须）
1. **线框图** (Wireframe): 确定布局和信息层级
2. **设计稿** (Design System): Figma 或 Adobe XD
3. **组件库** (Component Library): 按功能分类定义可复用组件
4. **交互原型** (Prototype): 演示关键动画和流程

### **编码时遵循的原则**
- 创建 `tailwind.config.js` 并将本文所有颜色/间距定义为 tokens
- 创建 `.vue` 组件对应每个设计组件
- 在 `styles/` 下定义全局 CSS 变量和动画
- 使用 CSS 类管理深色模式（`.dark` 前缀）
- 所有动画使用 `@apply` 或 Tailwind 的 `transition` 工具类

## 📋 总结：设计的三个层次

### 第一层：**清晰（Clarity）**
- 时间轴是焦点，一目了然
- 信息层级明确，重要信息突出
- 界面元素有清晰的用途和交互反馈

### 第二层：**温馨（Warmth）**
- 色彩温暖柔和，不刺眼
- 动画流畅自然，不生硬
- 文案亲切友好，有人性化

### 第三层：**丝滑（Smoothness）**
- 每个交互都有平滑的过渡
- 响应速度快，无延迟感
- 加载、保存、删除等操作都有反馈
